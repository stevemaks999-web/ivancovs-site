# Правила проекта Ivancovs

## Синхронизация с дашбордом
Любое изменение в проекте отражается на дашборде (https://dev.ivancovs.com/project-status/). Дашборд собирается из `PLAN.md`, GitHub (коммиты, PR, issues, проверки) и `scripts/build_status.py`.

После каждого изменения:
1. Обновить `PLAN.md`: отметить `[x]` сделанное, добавить новые задачи в нужную фазу, одна короткая строка на задачу. Если решение или правило изменилось, поправить блок «Правила аренды» и связанные пункты.
2. Новая работа идёт через ветку, PR и issue, чтобы её видно на табло GitHub. Коммитить в `staging`, прод только через PR в `main`.
3. Запушить в `staging`: CI пересоберёт `status.json` и задеплоит. При прямом деплое (`python3 deploy/deploy.py staging`) сначала `python3 scripts/build_status.py`.
4. Убедиться, что Gatekeeper и Deploy зелёные, а на дашборде цифры совпадают с `PLAN.md`.

## Прочее
- План виден клиенту: язык простой, без паролей, токенов, адресов хостинга и внутренних деталей.
- Репозиторий публичный: секреты только в GitHub Secrets и локальном `.env`.
- Формат фазы в `PLAN.md`: заголовок `## Фаза N. Название`, задачи `- [ ]` / `- [x]`. Парсер дашборда зависит от этого формата.
